0Pahami Alur Data Dulu

Sebelum ngetik kode, pahami arsitektur project ini. Semua modul CRUD di SELOG WMS mengikuti satu pola yang sama:

🖥️ Page (React) → dispatch → 📤 Action (getCustomersFetch) → ⚙️ Saga (intercept, panggil API) → 🌐 API Layer (axios ke backend) → ⬅️ hasil → Saga put → 📥 Reducer (getCustomersSuccess) → 💾 State berubah → 🖥️ Page re-render

Tiga istilah kunci yang harus nempel di kepala:

  • xxxFetch — action yang di-dispatch page, ditangkap saga. Reducer-nya cuma set isLoading = true.
  • xxxSuccess — action yang di-dispatch saga setelah API sukses. Reducer-nya simpan data ke state.
  • xxxFailure — sama, tapi untuk error. Simpan state.error.
Kunci: Saga TIDAK PERNAH menyimpan data langsung. Saga hanya memanggil API lalu mem-dispatch action Success/Failure. Yang ubah state selalu reducer.

1Types — Definisikan Bentuk Data

Mulai dari types karena semua file lain butuh tipe ini. Kita butuh 3 interface: data mentah customer, bentuk response API list, dan bentuk state redux.

types/wms-customer.type.ts 
import { BaseType, PaginationType } from "@sera-types/base.type";

/** Data satu customer, field backend apa adanya. Semua optional (+ createdAt/By, updatedAt/By dst). */
export interface WmsCustomer {
  no?: number;      // nomor urut tampilan (dihitung di reducer, bukan dari backend)
  id?: string;
  code?: string;
  name?: string;
  address?: string;
  phone?: string;
  createdAt?: string;
  createdBy?: string;
  updatedAt?: string;
  updatedBy?: string;
}

/** Bentuk response GET /customers (list dengan pagination). */
export interface GetWmsCustomersResponse extends BaseType {
  status?: boolean;
  message?: string;
  data?: WmsCustomer[];
  code?: string;
  pagination?: PaginationType;  // page, limit, totalData, totalPage
}

/** Bentuk slice state redux kita. */
export interface WmsCustomerState {
  data?: WmsCustomer[];
  isLoading?: boolean;
  error?: Error | string | null;
  options?: BaseType;                          // page, limit, search, dst utk tabel
  customerDetail: { data: WmsCustomer };       // utk halaman edit/detail
  createCustomer: { data: GetWmsCustomersResponse[] };
  updateCustomer: { data: GetWmsCustomersResponse[] };
  postCreateCustomer: { code: string; name: string };  // payload notifikasi sukses
  postUpdateCustomer: { id: string; name: string };
  postDeleteCustomer: { id: string; name: string };
}
Tip: kalau bingung bentuk response API, lihat response asli dari Postman/Network tab browser, lalu tulis interfacenya dari situ. Jangan menebak.

2API Layer — 5 Fungsi HTTP

Satu file, satu factory function, return object berisi semua fungsi API. Tidak ada logic lain di sini — hanya mapping endpoint.

libraries/api/wms-customer/index.ts 
import apiUrl from "@sera-libraries/common/api-url";
import { httpService } from "@sera-libraries/http-service";

const WmsCustomerApi = () => {
  // LIST + pagination + search + sort
  async function retrieveCustomers(payload: {
    page?: number; limit?: number;
    search?: string | null; searchBy?: string | null;
    order?: string | null; sort?: string | null;
  }) {
    return httpService.get(`${apiUrl.user}/customers`, { params: payload }).then((resp) => resp);
  }

  async function retrieveCustomerDetail(payload: { id: string }) {
    return httpService.get(`${apiUrl.user}/customers/${payload.id}`).then((resp) => resp);
  }

  async function createCustomer(payload: { code?: string; name?: string; address?: string; phone?: string }) {
    return httpService.post(`${apiUrl.user}/customers`, payload).then((resp) => resp);
  }

  async function updateCustomer(payload: {
    id: string;
    items?: { code?: string; name?: string; address?: string; phone?: string };
  }) {
    return httpService.put(`${apiUrl.user}/customers/${payload.id}`, payload.items).then((resp) => resp);
  }

  async function deleteCustomer(id: string) {
    return httpService.del(`${apiUrl.user}/customers/${id}`).then((resp) => resp);
  }

  return { retrieveCustomers, retrieveCustomerDetail, createCustomer, updateCustomer, deleteCustomer };
};

export default WmsCustomerApi;
Catatan: di project ini delete pakai httpService.del (bukan delete, karena reserved word). Endpoint customer ada di service apiUrl.user — sesuaikan dengan service backend kamu.

4Redux Slice — Actions + Reducers

Ini jantungnya. createSlice dari Redux Toolkit otomatis bikin action creators dari nama-nama reducer. Pola untuk tiap operasi selalu tiga-tiga: Fetch → Success → Failure.

redux/slices/wms-customer.slice.ts 
/* eslint-disable no-param-reassign */  // wajib! immer mutation butuh ini
import { createSlice, PayloadAction } from "@reduxjs/toolkit";
import { BaseType, PaginationType } from "@sera-types/base.type";
import { GetWmsCustomersResponse, WmsCustomer } from "@sera-types/wms-customer.type";
import initialState from "../states/wms-customer.state";

export const wmsCustomerState = createSlice({
  name: "wmsCustomers",   // nama ini jadi key state di store (Step 6)
  initialState,
  reducers: {
    // ===== LIST =====
    getCustomersFetch: (state, _action: PayloadAction<BaseType>) => {
      state.error = null;
      state.isLoading = true;      // cuma set loading, data diambil saga
    },
    getCustomersSuccess: (state, action: PayloadAction<GetWmsCustomersResponse>) => {
      const { data, pagination } = action.payload;
      const { page, limit, totalData, totalPage } = pagination as PaginationType;
      state.options = { ...state.options, page, limit, totalData, totalPage };
      if (data) {
        // hitung nomor urut tampilan: (page-1)*limit + index + 1
        state.data = data.map((c: WmsCustomer, index: number) => {
          const no = (page - 1) * limit + index + 1;
          return { ...c, no };
        });
      }
      state.isLoading = false;
    },
    getCustomersFailure: (state, action) => {
      state.isLoading = false;
      state.error = { ...action.payload };
    },

    // ===== DETAIL =====
    getCustomerDetailFetch: (state, _action) => { state.isLoading = true; state.error = null; },
    getCustomerDetailSuccess: (state, action) => {
      const { data } = action.payload;
      state.customerDetail.data = { ...state.customerDetail.data, ...data };
      state.isLoading = false;
    },
    getCustomerDetailFailure: (state, action) => { state.isLoading = false; state.error = { ...action.payload }; },

    // ===== CREATE =====
    createCustomerFetch: (state, _action) => { state.isLoading = true; state.error = null; },
    createCustomerSuccess: (state, action) => {
      const { data } = action.payload;
      state.createCustomer.data = data ?? [];
      state.postCreateCustomer = { code: data?.code, name: data?.name };  // utk notifikasi
      state.isLoading = false;
    },
    createCustomerFailure: (state, action) => { state.isLoading = false; state.error = { ...action.payload }; },
    postCreateCustomerClear: (state) => { state.postCreateCustomer = initialState.postCreateCustomer; },

    // ===== UPDATE =====
    updateCustomerFetch: (state, _action) => { state.isLoading = true; state.error = null; },
    updateCustomerSuccess: (state, action) => { /* pola sama dengan create */ },
    updateCustomerFailure: (state, action) => { /* pola standar */ },
    postUpdateCustomerClear: (state) => { state.postUpdateCustomer = initialState.postUpdateCustomer; },

    // ===== DELETE =====
    deleteCustomerFetch: (state, _action) => { state.isLoading = true; state.error = null; },
    deleteCustomerSuccess: (state, _action) => { state.isLoading = false; },
    deleteCustomerFailure: (state, action) => { state.isLoading = false; state.error = { ...action.payload }; },
    postDeleteCustomerNotification: (state, action) => {  // dipakai table utk nama yang dihapus
      state.postDeleteCustomer = { id: action.payload.id, name: action.payload.name };
    },
    postDeleteCustomerClear: (state) => { state.postDeleteCustomer = initialState.postDeleteCustomer; },
  },
});

// action creators + reducer di-export dua-duanya
export const { actions: wmsCustomerActions, reducer: wmsCustomerReducers } = wmsCustomerState;
export default wmsCustomerReducers;
Penting — error commit kemarin: reducer yang tidak pakai action HARUS dinamai _action (dengan garis bawah). ESLint rule no-unused-vars project ini hanya mengizinkan unused arg yang diawali _. Lupa ini = pre-commit hook gagal.

5Redux Saga — Side Effects

Saga bertugas: (1) menangkap action ...Fetch, (2) memanggil API, (3) dispatch Success/Failure, (4) kadang routing setelah sukses. Satu saga worker per operasi, lalu satu saga watcher yang mendaftarkan semuanya.

redux/sagas/wms-customer.saga.ts 
import { PayloadAction } from "@reduxjs/toolkit";
import WmsCustomerApi from "@sera-libraries/api/wms-customer";
import { wmsCustomerActions } from "@sera-redux/slices/wms-customer.slice";
import { AxiosResponse } from "axios";
import Router from "next/router";
import { all, call, put, takeEvery } from "redux-saga/effects";

// ===== WORKER: LIST =====
function* getCustomers(params: PayloadAction<BaseType>): Generator<unknown, void, AxiosResponse> {
  try {
    const result = yield call(WmsCustomerApi().retrieveCustomers, { ...params.payload });
    if (result?.status === 200)
      yield put(wmsCustomerActions.getCustomersSuccess(result.data));
  } catch (error: any) {
    yield put(wmsCustomerActions.getCustomersFailure({
      status: error.status, statusText: error.statusText, statusCode: error.data,
    }));
  }
}

// ===== WORKER: CREATE — perhatikan Router.push setelah sukses =====
function* createCustomer(params: PayloadAction<any>): Generator<unknown, void, AxiosResponse> {
  try {
    const result = yield call(WmsCustomerApi().createCustomer, { ...params.payload });
    if (result?.status === 201 || result?.status === 200) {
      yield put(wmsCustomerActions.createCustomerSuccess({ data: params.payload }));
      Router.push("/user-management/customers");   // balik ke list setelah sukses
    }
  } catch (error: any) {
    yield put(wmsCustomerActions.createCustomerFailure({
      status: error.status, statusText: error.statusText, statusCode: error.data,
    }));
  }
}

// ===== WORKER: UPDATE & DELETE & DETAIL — pola identik, tinggal ganti fungsi API =====

// ===== WATCHER: daftarkan semua worker =====
function* WmsCustomerSaga() {
  yield all([
    takeEvery(wmsCustomerActions.getCustomersFetch.type, getCustomers),
    takeEvery(wmsCustomerActions.getCustomerDetailFetch.type, getCustomerDetail),
    takeEvery(wmsCustomerActions.createCustomerFetch.type, createCustomer),
    takeEvery(wmsCustomerActions.updateCustomerFetch.type, updateCustomer),
    takeEvery(wmsCustomerActions.deleteCustomerFetch.type, deleteCustomer),
  ]);
}

export default WmsCustomerSaga;

Kamus istilah saga

EffectArtinya
takeEvery"setiap kali action ini muncul, jalankan worker ini"
call(fn, arg)panggil fungsi (API) secara non-blocking
put(action)dispatch action baru (seperti dispatch() biasa)
all([...])jalankan beberapa effect paralel

10Komponen Table — List + Search + Pagination + Hapus

Tabel menerima props dari halaman list: dataSource, options, loading, onFetch, onDelete. Tanggung jawabnya: render kolom, tombol aksi (edit/detail/hapus dengan cek permission), search box, dan modal konfirmasi hapus.

components/pages/user-management/customers/customer-table.tsx — kerangka inti 
// ...imports Button, Modal, Input, Select, Table, icons, antd, dll...

const CustomerTable = ({ dataSource, options, loading, onFetch, onDelete }: Props) => {
  const { t } = useTranslation(undefined, { keyPrefix: "customerManagement" });
  const baseLink = ROUTES.USER_MANAGEMENT.CUSTOMERS;
  const [searchByOption, setSearchByOption] = useState("name");
  const [listOptions, setListOptions] = useState<BaseType>({
    page: 1, limit: 10, search: null, searchBy: "name", order: null, sort: null,
  });
  const [showDeleteConfirm, setShowDeleteConfirm] = useState(false);
  const [selected, setSelected] = useState<{ id: string; name: string }>({ id: "", name: "" });

  // setiap listOptions berubah (pindah halaman / search) → fetch ulang
  useEffect(() => { onFetch(listOptions); }, [listOptions]);

  const showDeleteModal = (obj: { id: string; name: string }) => {
    setShowDeleteConfirm(true); setSelected(obj);
  };

  const COLUMNS = [
    { title: t("table.columns.no"), dataIndex: "no" },
    { title: t("table.columns.code"), dataIndex: "code" },
    { title: t("table.columns.name"), dataIndex: "name" },
    // ...address, phone, createdAt
    {
      title: t("table.columns.actions"),
      render: (_: unknown, record: WmsCustomer) => (
        <>
          // tiap tombol dicek permission dulu lewat useCheckPermission
          {useCheckPermission(...edit) && <Link href={`${baseLink}/edit/${record.id}`}>✏️</Link>}
          {useCheckPermission(...delete) &&
            <Button onClick={() => showDeleteModal({ id: record.id!, name: record.name! })}>🗑️</Button>}
        </>
      ),
    },
  ];

  return (
    <>
      <Table
        columns={COLUMNS}
        dataSource={dataSource}
        loading={loading}
        pagination={{ ...options, onChange: (page) => setListOptions((p) => ({ ...p, page })) }}
        // search bar + dropdown "cari berdasarkan" di prop search
      />

      // modal konfirmasi hapus
      <Modal
        open={showDeleteConfirm}
        onCancel={() => setShowDeleteConfirm(false)}
        onOk={() => { onDelete({ id: selected.id }); setShowDeleteConfirm(false); }}
      >
        {t("confirmDelete")} {selected.name}?
      </Modal>
    </>
  );
};
Penjelasan pola listOptions: state lokal ini adalah "sumber kebenaran" untuk query tabel (halaman berapa, cari apa, sort apa). Setiap berubah → useEffect fetch ulang. Sederhana dan selalu sinkron.

  const { t } = useTranslation(undefined, { keyPrefix: "customerManagement" });

  const handleSubmit = () => {
    form
      .validateFields()              // jalankan rules required dll
      .then((values) => { createCustomer(values); })   // dispatch createCustomerFetch
      .catch(() => undefined);        // error validasi sudah ditampilkan antd
  };

  // kalau saga gagal, state.customers.error terisi → tampilkan notifikasi
  useEffect(() => {

      MessageHandler().error(t("notification.addFailed"));
    }
  }, [customers.error]);

  return (
    <LayoutUserManagement titlePage={t("form.title")} locationUrlList={...}>
      <CustomerForm form={form} loading={!!loading.isLoading} onSubmit={handleSubmit} />
    </LayoutUserManagement>
  );
};

const mapDispatchToProps = { createCustomer: wmsCustomerActions.createCustomerFetch };
export default connect(mapStateToProps, mapDispatchToProps)(CustomerAdd);

13Halaman Edit

Dua perbedaan dari add: (1) ambil id dari URL lewat useRouter().query, (2) fetch detail dulu lalu isi form dengan form.setFieldsValue.

pages/user-management/customers/edit/[id].tsx 
const CustomerEdit = ({ loading, updateCustomer, getCustomerDetail, customers }: {...}) => {
  const router = useRouter();
  const { id } = router.query;        // ← dari URL /edit/[id]
  const [form] = Form.useForm();

  // 1) begitu id tersedia → fetch detail customer
  useEffect(() => {
    if (id) getCustomerDetail({ id: id as string });
  }, [id]);

  // 2) begitu detail masuk ke state → isi form
  useEffect(() => {
    const d = customers.customerDetail.data;
    if (d?.id) {
      form.setFieldsValue({ code: d.code, name: d.name, address: d.address, phone: d.phone });
    }
  }, [customers.customerDetail.data]);

  const handleSubmit = () => {
    form.validateFields().then((values) => {
      updateCustomer({ id: id as string, items: values });  // ← payload beda dari create
    });
  };

  // render-nya sama dengan add: CustomerForm + onSubmit
};

const mapDispatchToProps = {
  updateCustomer: wmsCustomerActions.updateCustomerFetch,
  getCustomerDetail: wmsCustomerActions.getCustomerDetailFetch,
};
Dua useEffect = dua tahap reaksi: yang pertama bereaksi terhadap id (URL), yang kedua bereaksi terhadap customerDetail.data (state redux). Ini pola standar halaman edit di project ini.

  1. Buka /user-management/customers → tabel terisi data
